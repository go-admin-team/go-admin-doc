## 概要

[go-admin](https://github.com/go-admin-team/go-admin) は管理画面アプリケーション向けのフレームワークです。バックエンドは Gin・GORM・Casbin、フロントエンドは Vue 3 と Element Plus をベースにしており、Arco Design 版・Ant Design 版も用意されています。

プロジェクトは 2 つのリポジトリで構成されています。[go-admin](https://github.com/go-admin-team/go-admin) がバックエンド、[go-admin-ui](https://github.com/go-admin-team/go-admin-ui) がフロントエンドです。フレームワーク側で標準化されたレイヤー構成と開発フローを提供しているため、プロジェクトの規模が大きくなっても見通しを保てます。

このフレームワークが解決するのは重複作業です。認証・権限・ユーザーおよび部門管理といった、どの管理画面でも作り直すことになる部分はあらかじめ用意されているので、新しいプロジェクトではビジネスロジックの実装からすぐに取りかかれます。

## こんな場面に向いています

go-admin が想定しているのは、**権限モデルが明確な社内システム**——管理コンソールや運用プラットフォーム、業務基盤など、ロールの分離とデータの可視範囲の制御が必要な場面です。

向いているケース：

- RBAC によるロール権限が必要で、データの可視範囲を組織図に沿って制御したい；
- 1 つのコードベースで複数テナントにサービスを提供したい；
- テーブル構造が比較的定型的で、大半がコードジェネレーターで生成できる標準的な CRUD である；
- チーム規模が小さく、認証・権限・ロギングといった基盤部分をゼロから構築する時間を省きたい。

慎重に検討したほうがよいケース：

- 高並行のコンシューマー向けサービスを構築している——このフレームワークの重点は管理系ツールであり、高スループット向けの最適化ではありません；
- すでに成熟した権限体系とアカウントセンターがある——統合コストがメリットを上回る可能性があります。

## 特徴

- すぐに使える
- RESTful API の規約に準拠
- Gin ベースの Web フレームワークで、認証・CORS・アクセスログ・トレース ID などのミドルウェアを標準搭載
- Casbin による RBAC アクセス制御
- JWT 認証
- swaggo による Swagger ドキュメント
- GORM ベースのストレージで、複数のデータベースエンジンに対応可能
- 設定は構造体に直接マッピング
- コードジェネレーター
- フォームビルダー
- 単体テスト（順次追加中）

## 主な機能

1. **ユーザー管理** — システムを操作するアカウント。
2. **部門管理** — 組織構造（会社・部門・チーム）のツリー。データ権限の範囲設定の基礎になります。
3. **役職管理** — ユーザーが担当する役職。
4. **メニュー管理** — ナビゲーション、操作権限、ボタン単位の権限キー。
5. **ロール管理** — ロールごとのメニュー権限と、そのロールが制限されるデータ範囲。
6. **辞書管理** — システム全体で使う固定的な参照データ。
7. **パラメータ管理** — 実行時の設定値。
8. **操作ログ** — 通常の操作とエラーの両方の記録。
9. **ログインログ** — 失敗したログインを含むサインイン記録。
10. **API ドキュメント** — コードから自動生成。
11. **コード生成** — テーブルに対する CRUD を、画面上の設定だけで生成。
12. **フォームビルダー** — ドラッグ＆ドロップでページレイアウトを組み立て。
13. **サーバー監視** — ホストの基本的な情報を表示。
